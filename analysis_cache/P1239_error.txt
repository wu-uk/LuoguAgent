1`，每一轮都会使当前位的数字 d 完整地循环 `weight` 次。因此，这部分贡献了 `next_ * weight` 次。\n    *   **当前位的贡献**：\n        *   如果 `current > d`，则在当前轮中，数字 d 出现了 `weight` 次。\n        *   如果 `current == d`，则在当前轮中，数字 d 出现了 `prev_ + 1` 次（从 `...d0` 到 `...d(prev_)`）。\n        *   如果 `current < d`，则在当前轮中，数字 d 不出现。\n\n2.  **当 `d == 0` 时**：情况特殊，因为页码没有前导零。\n    *   **高位的贡献**：当最高位为 `next_` 时，低位不可能有前导零。所以对于数字0，高位不能从0开始。高位应该从 1 变化到 `next_ - 1) * weight + 1`: 这是比较容易出错的地方。因为不能有前导零，所以高位最小为 1。因此，有 `higher - 1` 个完整的 `weight` 循环。`+1` 是为了修正当 `higher=0` 时的情况（例如 n=5）。\n    *   如果 `current > 0`，`count[0] += lower + 1` 当前位为0时，统计所有可能的低位组合。\n    *   如果 `current == 0`，`count[0] += weight`。  这个逻辑依然有些绕。\n\n让我们采用题解中更健壮的方法来避免对0的特殊处理出错。该方法从低位到高位遍历，使用 `r` 变量记录当前是第几位（从0开始），`ans` 变量为当前位的权重 `10^r`。\n\n`x = (n / ans) % 10` 是当前位的数字，`y = n % ans` 是低位的数值。\n\n1.  **`for i=0 to 9 do a[i] += r * x * ans / 10`**：这一步计算了由高位数字 `x` 决定的，在 `r` 个低位上数字 `0-9` 完整循环的次数。设当前位是 `weight = 10^r`。对于一个固定的当前位 `x`，`r` 个低位共有 `weight` 个数（`0` 到 `weight-1`）。在这 `weight` 个数中，每个 `0-9` 在每个低位上出现的次数是 `weight / 10`。总共 `r` 个低位，所以总次数是 `r * (weight / 10)`。这个情况会重复 `x` 次（由高位 `next_` 决定）。所以是 `r * x * (weight/10)`。\n\n2.  **`for i=0 to x-1 do a[i] += ans`**：这一步计算当前位从 0 变到 `x-1` 时，每个数字 `i` 作为当前位的贡献。每次变化，低位可以从 `0` 变到 `ans-1`，所以每个数字 `i` 会贡献 `ans` 次（`i` 在当前位）。这对应了 `current > i` 的情况。\n\n3.  **`a[x] += y + 1`**：这一步处理当前位数字 `x` 自身。当当前位恰好是 `x` 时，低位可以从 0 变化到 `y`（`n%ans`），所以数字 `x` 在当前位出现了 `y+1` 次。这对应了 `current == i` 的情况。\n\n4.  **`a[0] -= ans`**：**关键的修正**。前面的计算把 `0` 当作了普通数字，包含了形如 `00...0`, `01...1` 等带前导零的数。在 `ans` 的权重下（比如 `ans=100`），`00...00` 到 `00...99` 这 `ans` 个数都是无效的页码。`ans` 的权重下，多算的 `0` 的个数正好是 `ans` 个。例如，计算到百位（`ans=100`），我们假设了 `000-099` 也存在，导致百位上的 `0` 多算了 100 次。同理，计算到十位（`ans=10`），`00-09` 中十位的 `0` 多算了 10 次。这一步减去的是当前权重下多算的0，是处理前导零问题的核心。从高到低处理时，在每一个权重为 `ans` 的位上，都要多算 `ans` 个0。\n\n最后，从低到高循环处理完所有位后，数组 `a` 中就存储了 `0-9` 在 1 到 n 中出现的总次数。",
