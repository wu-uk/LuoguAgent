
{"detailed_solution": "本题要求在线处理多个区间查询，返回每个区间内最小未出现的自然数（mex）。由于 n 和 m 的规模都达到了 2*10^5，朴素的 O(n) 每次查询或 O(n^2) 的暴力方法都会超时。我们需要一种更高效的离线算法。\n\n### 方法一：回滚莫队\n\n#### 1. 算法思想\n\n莫队算法是一种优秀的离线处理区间查询的算法。它通过对询问进行排序，利用指针的移动来复用计算结果，将时间复杂度优化到 O((n+m)*√n)。\n\n然而，对于 mex 查询，标准莫队算法存在一个问题：增加一个元素时，mex 值可能会减小，而我们很难高效地更新它。相反，当我们删除一个元素 `x` 时，如果 `x` 在当前区间内的计数变为 0，那么新的 mex 只可能是 `mex` 和 `x` 中的较小者，这个更新是 O(1) 的。\n\n基于这个观察，我们使用一种“回滚莫队”（Rollback Mo's Algorithm）的变种，它在处理每个块内的询问时，只进行删除操作。这被称为“只减不加”的回滚莫队。\n\n#### 2. 具体步骤\n\n1.  **分块**：将长度为 n 的数组分成 `√n` 个块。我们定义一个数组 `bel[i]` 表示元素 `a[i]` 属于哪个块。\n\n2.  **排序询问**：将所有询问 `(l, r, id)` 按照以下规则排序：\n    *   首先，按照左端点 `l` 所属的块 `bel[l]` 升序排序。\n    *   如果两个询问的 `bel[l]` 相同，则按照右端点 `r` **降序**排序。\n\n    这个排序规则是实现“只减不加”的关键。对于同一个块内的询问，`r` 从大到小处理，意味着右指针只需要不断向左移动（删除元素）。\n\n3.  **初始化**：预处理整个数组 `[1, n]` 的 mex 值，记为 `global_mex`。我们可以用一个计数数组 `cnt`，遍历整个数组，统计每个数 `a[i]` 的出现次数。然后从 0 开始向上遍历，第一个 `cnt[i]` 为 0 的数就是 `global_mex`。同时，维护一个全局的计数器 `cnt` 和当前的 mex 值 `cur_mex`。\n\n4.  **处理询问**：我们逐个块进行处理。对于第 `k` 个块：\n    *   设块的左边界为 `Lk`，右边界为 `Rk`。\n    *   初始化两个指针：`l = Lk` 和 `r = n`。维护的当前区间是 `[l, r]`。这个区间的 mex 值就是 `global_mex`。\n    *   遍历所有左端点 `bel[l] == k` 的询问。由于我们已经按 `r` 降序排序，对于这些询问，我们只需要不断将右指针 `r` 向左移动，直到 `r` 等于询问的右端点。在移动过程中，每删除一个元素 `a[r]`，我们更新 `cnt[a[r]]--`。如果 `cnt[a[r]]` 变为 0，说明 `a[r]` 从当前区间消失了，它可能成为新的 mex，因此我们更新 `cur_mex = min(cur_mex, a[r])`。\n    *   此时，`[l, r]` 是一个基础区间，它的 mex 是 `cur_mex`。对于当前询问 `[q_l, q_r]`（其中 `q_l >= Lk` 且 `q_r <= r`），我们还需要处理左端点。我们用一个临时变量 `tmp_mex = cur_mex`。然后，一个临时指针 `tmp_l` 从 `l` 开始向右移动到 `q_l`。每移动一步，相当于从 `[tmp_l, r]` 中删除 `a[tmp_l]`。我们同样更新 `cnt[a[tmp_l]]--`，如果 `cnt[a[tmp_l]]` 变为 0，就更新 `tmp_mex = min(tmp_mex, a[tmp_l])`。最后得到的 `tmp_mex` 就是 `[q_l, q_r]` 的答案。\n    *   **回滚**：处理完一个询问后，左指针 `tmp_l` 的影响必须被撤销，以便处理下一个 `r` 更小的询问。我们通过将 `tmp_l` 移动回 `l` 来实现回滚。在这个过程中，我们只需将之前删除的元素重新加入即可，即 `cnt[a[tmp_l]]++`。这个过程是 O(1) 的，因为我们只是恢复了临时状态。\n    *   当块 `k` 的所有询问都处理完后，我们需要为下一个块 `k+1` 做准备。此时，`r` 指针停留在块 `k` 的所有询问中最小的 `r` 处。我们需要将 `r` 重新移到数组末尾 `n`，并重新加入所有被删除的元素（`cnt[a[r]]++`），同时更新 `cur_mex`。这个过程可以被优化，我们可以在处理完一个块后，直接将 `l` 指针移到下一个块的左边界，相当于删除了整个前 `k` 个块的元素。这个过程只用做一次，而不是对每个询问都做，从而保证了总复杂度。\n\n5.  **处理同块询问**：对于 `l` 和 `r` 在同一个块内的询问，我们直接暴力求解，因为一个块的长度是 `√n`，处理一个这样的询问最多需要 `O(√n)` 的时间。总共有 `m` 个询问，这部分的总复杂度为 `O(m√n)`，可以接受。\n\n#### 3. 复杂度分析\n\n*   **分块和排序**：`O(n log n + m log m)`。
*   **预处理 global_mex**：`O(n)`。
*   **主循环**：外层循环遍历 `√n` 个块。
    *   右指针 `r` 在处理每个块时，从 `n` 移动到该块中最小的 `r`，在处理完一个块后，又从那个最小 `r` 移回 `n`。在整个算法过程中，`r` 指针最多移动 `O(n√n)` 次？不，更精确地，`r` 在每个块内只向左移动，移动次数为 `O(n)`。处理完所有块，`r` 总共向左移动 `O(n)` 次，向右移动 `O(n)` 次。所以 `r` 的移动是 `O(n)`。
    *   左指针 `l` 在处理每个询问时，临时向右移动，然后回滚。这部分是 `O(m√n)`。
    *   块间的 `l` 指针移动，总共 `O(n)`。
*   综合来看，复杂度主要由 `O((n+m)√n)` 主导。对于 `n,m=2*10^5`，`√n` 约等于 450，总运算量约为 `1.8*10^8`，在 C++ 中可以接受。\n\n### 方法二：值域线段树\n\n这是一种更巧妙、复杂度更优的方法，可以达到 `O((n+m)log n)`。\n\n#### 1. 算法思想\n\n我们将所有询问按左端点 `l` 从小到大排序。我们用一个指针 `now` 表示当前处理的数组前缀 `[1, now-1]`。当我们处理完所有 `l <= now-1` 的询问后，我们开始考虑 `a[now]` 的影响，并将 `now` 向右移动。\n\n核心思想是：一个元素 `a[i]` 对 mex 的影响，仅限于那些左端点 `l` 在 `i` 之前，且右端点 `r` 在 `i` 之后，并且 `l` 不在 `i` 和 `next_pos[a[i]]-1` 之间的查询。其中 `next_pos[a[i]]` 是 `a[i]` 下一次出现的位置。\n\n考虑 `a[now]`。它会影响哪些区间的 mex 呢？对于任何一个左端点 `l <= now` 的区间 `[l, r]`，如果 `a[now]` 是这个区间的 mex，那么说明 `a[now]` 在该区间内没有出现过，但比 `a[now]` 小的数都出现过。一个更简单的理解是：当我们把左端点从 `now-1` 移动到 `now` 时，我们“删除”了 `a[now]` 这个数。这会影响所有 `l <= now` 的区间。具体来说，对于那些 `l<=now` 且 `r>=now` 的区间，如果 `a[now]` 原来在区间里，现在就出去了，这可能会让 mex 变大。如果 `a[now]` 原本就不在区间里（因为 `l>now`），那没有影响。这个思路比较绕。\n\n我们换个思路：对于一个固定的左端点 `l`，我们想快速回答所有 `[l, r]` 的查询。我们考虑右端点 `r` 从 `l` 到 `n` 增加的过程，mex 如何变化。这个过程是 `O(n)` 的。我们需要对所有 `l` 都做一遍，太慢了。\n\n**正确的思路**：离线处理，按 `l` 排序。我们维护一个数据结构，对于每个可能的右端点 `r`，存储当前左边界下的 `mex([l, r])` 的一个**上界**。`l` 从 1 变化到 `n`，数据结构动态更新。\n\n1.  **预处理**：用 `next_occurrence` 数组记录 `next_pos[i]`，即 `a[i]` 下一次出现的位置。
2.  **初始化**：建一棵线段树，节点代表一个 `r` 的区间。线段树的每个节点 `p` 存一个值 `min_val[p]`，表示该节点所覆盖的 `r` 范围内，mex 的一个上界。初始时，对于左边界 `l=1`，我们可以用前缀和的方法快速算出 `mex([1, r])` 的变化。`mex([1,1])` 然后是 `mex([1,2])` ... `mex([1,n])`。这个序列的值可以被更新到线段树的叶子节点 `r` 上。`min_val[r] = mex([1, r])`。
3.  **处理排序后的询问**：询问按 `l` 从小到大排序。我们用一个指针 `curr_l`，表示当前处理的左边界。
    *   `curr_l` 初始化为 1。
    *   对于每个询问 `(l, r, id)`，我们需要将 `curr_l` 移动到 `l`。这意味着我们要“删除” `a[curr_l]`, `a[curr_l+1]`, ..., `a[l-1]` 这些数的影响。
    *   当 `curr_l` 向右移动到 `curr_l+1` 时，我们“删除” `a[curr_l]`。这个删除操作会影响到哪些 `r` 对应的 mex 呢？对于 `r >= curr_l`，`a[curr_l]` 可能从区间 `[curr_l, r]` 中消失。如果 `a[curr_l]` 消失了，mex 可能会变大。具体影响范围是 `r` 在 `[curr_l, next_pos[a[curr_l]]-1]` 这个区间内的查询。因为 `a[curr_l]` 在这个范围内只出现一次，就是 `curr_l` 这个位置。
    *   所以，删除 `a[curr_l]` 的操作，等价于：对所有 `r` 在 `[curr_l, next_pos[a[curr_l]]-1]` 范围内的 `mex` 值，它们的新值不能小于 `a[curr_l]`。换句话说，这些位置的 `mex` 值需要和 `a[curr_l]` 取一个 `min`。这个操作可以用线段树的区间更新 `min` 来完成。我们把 `a[curr_l]` 作为一个“限制”或“膜”打到线段树的 `[curr_l, next_pos[a[curr_l]]-1]` 这个区间上。
    *   我们不断更新 `curr_l` 直到它等于询问的 `l`。然后，我们查询线段树在位置 `r` 上的值，就是 `mex([l, r])` 的答案。
\n\n#### 2. 具体步骤\n\n1.  **预处理 next_pos**：用 `std::map` 或一个数组，从后往前遍历数组，记录每个值 `a[i]` 的下一个出现位置 `next_pos[i]`。
n\n2.  **排序询问**：按 `l` 升序排序。
n\n3.  **初始化线段树**：树上的每个点初始值设为一个很大的数（如 `INF = n+5`）。然后用一个 `while` 循环，计算 `mex([1, r])` 的变化，并将其更新到线段树的叶子节点 `r` 上。

    *   答案 `ans[id] = query(1, 1, n, r)`。
